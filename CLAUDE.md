# FSM PRO — рабочие инструкции проекта

## Зачем этот файл
Используй этот файл как обязательный ориентир при любых изменениях в проекте FSM PRO.

## Что смотреть в первую очередь
- `reference-style/` — визуальные и продуктовые референсы
- `FSM_System_Architecture_and_Specification.md` — архитектура и правила системы
- `src/index.css` — базовая палитра и фоновые цвета проекта
- `database_schema.sql` — модель данных
- `bossyoki-dashboard-preview.html` — прототип-ориентир (НЕ жёсткое ТЗ, а визуальная цель)

## Статусы задач
Только 5 статусов:
- Новая
- Назначена
- В работе
- На проверке
- Выполнена

Просрочка — визуальный флаг `isOverdue` на карточке, а не отдельный статус.
Возврат на доработку → задача снова «В работе» (не отдельный статус).

## Роль руководителя (админка)
4 раздела с пилюлями:
- **Главная** — 4 KPI-карточки (В работе, Ждут проверки, Нужно исправить, Активных бригад)
- **Задачи** — двухколоночный макет 1.35fr / 0.95fr, чат с рабочими, быстрое создание задачи
- **Бригады** — карта бригад, согласование/возврат отчётов, формирование Акта (PDF)
- **Проверка** — экспорт в Excel

Компоненты: `DashboardAdmin`, `TaskListScreen`, `BrigadeScreen`, `ReviewScreen`, `DocsViewer`, `ChatScreen`

## Роль бригады (мобильная часть)
2 раздела:
- **Мои задачи** — список задач → карточка (адрес, клиент, телефон, описание) → начало работы → фото → комментарий → отправка на проверку
- **Помощь** — справка, связь с диспетчером, сброс демо

Компоненты: `TaskListScreen`, `TaskDetailScreen`, `WorkScreen`, `HelpScreen`, `MobileFrame`

### Первый экран (стартовый)
- Логотип FSM PRO
- Кнопка «Попробовать» — вход в демо-режим
- Кнопка «Войти по коду» — модалка с полем ввода

### Демо-режим
- Жёлтая плашка «Учебный режим»
- 4 шага обучения при первом входе
- Данные не сохраняются на сервере

### Убрано из мобильной части (осталось только в админке)
- PDF-акты, подписи клиентов
- Материалы/склад
- Карта маршрута
- Многошаговый чек-лист
- Вкладка «Профиль» (заменена на «Помощь»)
- Шапка с переключателем ролей
- «Сценарий мастера»

## Чат между диспетчером и рабочими
Сквозная связка работает через общий стор в `AppContext` (`fsm_chat` в localStorage).
Сообщения доступны с обеих сторон (диспетчер и бригада).

## Как работать
- Сначала смотри стиль и структуру в `reference-style/`
- Новые экраны и компоненты делай в том же тоне, что и исполнительская часть FSM PRO: светлый фон, белые карточки, синий акцент, зелёные статусы
- Важные действия должны быть крупными и чаще находиться внизу экрана, особенно на телефоне
- `bossyoki-dashboard-preview.html` — прототип-ориентир, а не жёсткое ТЗ. Админка разработана как профессиональная реализация с учётом этого прототипа, но не тупо скопирована
- Не ломай существующие экраны без необходимости

## Цель продукта
FSM PRO — это офлайн-first система выездных работ с понятным диспетчерским дашбордом, мобильной частью и акцентом на быстрый контроль статусов.

### 1. Интеграция базы данных — Supabase (главный следующий шаг)
Выбранный путь: **React (существующий fsm-app) + Supabase** (не переписывать на Flutter — фронтенд уже готов!).
- В `.env` уже есть `SUPABASE_URL` и `SUPABASE_KEY` (connection string pooler 6543 — для серверного использования).
- Для браузера нужен **anon publishable key** (публичный) — connection string в клиентский код НЕ класть.
- Таблицы: `companies / users / teams / team_members / sites / tasks / photos / comments` (совпадает с `database_schema.sql`).
- Статусы задач: `new → assigned → in_progress → review → done`.
- RLS включить на КАЖДОЙ таблице (политика = автоматический WHERE; руководитель видит свою компанию, бригадир — свою бригаду).
- Fото — в Supabase Storage (таблица `photos` хранит ссылки), тип: before/progress/after.
- Auth — вход руководителя и бригад.
- Realtime — руководитель сразу видит изменения.

### 2. После базы — офлайн-режим с синхронизацией
Сейчас офлайн работает чисто локально (IndexedDB). После подключения Supabase — добавить отложенную синхронизацию:
`телефон сохранил задачу → интернет появился → данные ушли в Supabase`.

`deploy_gh.py` сам загрузит все файлы из `dist/` и обновит Pages (файлы перезапишутся с новыми sha).
